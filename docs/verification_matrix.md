## How to read the last column

* **reproduced**: the same program run again gives the same output. It shows that a result is stable, not that it is right.
* **independently re-verified**: either (a) a second implementation, written separately from the program that produced the result (different code, ideally
  a different method), or (b) a certificate checker: a short program that checks a stored certificate and shares nothing with the program that found it.
  The row says which of the two it is.
* Final column: **yes** = independently re-verified in the sense above, by something shipped here and run today; **partly** = only reproduced, or only
  some of the numbers of the claim are re-verified, or the second implementation is numerical where the claim is rigorous; **no** = nothing shipped
  re-verifies it (literature claims "cited, not re-verified" are listed as **no** and again at the end).
* Column "who": A, B and C are internal labels for the three parts of the team's work (A = certificates, energy bounds, vector-to-basis theorem, detection test, dimension ten; B = structure theory and its Lean project, now `lean_structure/`;
  C = certificate audit and full rerun, now `openai_check/full_audit/`); all three are the team's own work. "literature" = cited prior work. Status tags are those of the report (proved, Lean-checked, interval-certified,
  computed, numerical, cited, conditional, conjectured, reported).
* Commands are run from the repository root; steps `S01` to `S41` are the steps of `verify_all.sh`, which runs them all on a temporary copy of the
  repository (so scripts that overwrite stored files never touch the originals) and prints the claim ids each supports. The log of the run is
  `docs/verify_all.log`. Every script was run under `nice -n 5` on a 2-core machine that was shared with other jobs, so runtimes are upper estimates.
* Tags such as `[C-finite-opt]` in the output of `checks/check_report_arithmetic.py` name sections of that script; the claim ids below say which
  tags support which claim.

## What `verify_all.sh` does and does not cover

It runs S01 to S41 (the fast checks), about 11 minutes on two shared cores, on a copy of the repository, and exits non-zero if any step exits non-zero or
if an expected output line is missing. Its log is `docs/verify_all.log`. It does not run: Qiskit simulations, the full SDP re-solves, the 1.2-million-start
searches, `openai_check/`, or anything that needs the OpenAI repository, the Lean build or the native rerun environment. A claim marked **yes** therefore
means "re-verified by something that `verify_all.sh` runs", with the exceptions of C8 to C10 (partly, via `openai_check/`) and the Lean rows C65 to C69
(the Lean build needs a Mathlib checkout and is run by hand: `lake build` from the repository root; the log is `lean/BUILD_LOG.txt`; not part of `verify_all.sh`).
